# 项目证据、现有结果与问题审计

本文件严格区分：**观察证据、数学推论、尚未验证的假设和推荐动作**。

## 1. 项目当前真正贡献

当前项目已经不只是“提出一个分数”。可成立的贡献是：

1. 将 GeoFM/RSFM 的平均性能评价改写为 deployment-slice tail-risk audit；
2. 建立从规范化 audit table、支持预检、正式 BWER 到结果包的完整流水线；
3. 用四类任务展示事件、地理、sensor modality 和全球地图协议下的部署差异；
4. 已实现 Raw、Standardised、Selective 和部分 Conformal 审计原型；
5. 已保存大量踩坑、数据合同、预处理、split、Drive cache 和 canonical lineage 经验，显著降低重跑风险。

当前尚不能稳定成立的强主张是：“BWER 已经是经过有限样本认证、跨协议可直接比较的成熟公平性标准。”原因不是四实验不够，而是总体参数、估计器和推断单位还没有在代码中统一。

## 2. 四实验目前分别证明什么

### 2.1 Sen1Floods11

**已观察：**

- 项目完成了 Prithvi task-learning 分割、监督 U-Net、光谱基线和事件级分析；
- 事件风险差异明显，Somalia/Pakistan 等事件曾进入最差尾部；
- LOEO 与普通 split、冻结诊断与正式分割协议之间存在区别，现有结果不能全部放在同一模型排名表；
- 11 个事件使旧 `ceil(.1×11)` 取两个完整事件，实际尾部质量为 18.18%。

**正式能说：**BWER 能把灾害事件作为部署单元，暴露平均分数掩盖的事件异质性。

**尚不能说：**某个 FM 在相同训练、传感器、split 和解码器协议下已被严格证明比所有监督基线更公平。

### 2.2 fMoW-Sentinel

**已观察：**

- 30k 数据具有 location-disjoint split、62 类和完整地理元数据；
- ResNet-50 与 DOFA 的平均风险和 country-tail 风险排序可能不同；
- 145 个有效国家的支持分布为最小约 20、中位约 39、最大约 366；
- 旧 BWER1 与 fractional BWER 点值差异通常很小，但零差异模拟中 plug-in BWER 均值可约为 0.1088；
- 当前旧表通常只有 top confidence、预测和正确性，不能还原完整 conformal prediction set。

**正式能说：**地理不相交协议下，平均能力与地理尾部可靠性不是同一排序问题；该任务为 ranking divergence 提供了强候选证据。

**尚不能说：**排名反转已经通过共同支持、成对推断和独立确认。新框架可能保留部分反转，也可能证明一部分旧反转来自选择噪声。

### 2.3 reBEN / CROMA

**已观察：**

- CROMA 的 S1、S2、S1+S2 已完整跑通；
- 现有 country BWER 约为 S1 0.1588、S2 0.1055、fusion 0.0724；
- 这提示融合可能优先改善最脆弱部署切片，而不只改善均值；
- 目前只有一个多模态架构，无法区分“多模态的一般规律”与“CROMA 特性”。

**正式能说：**同一架构内，不同 sensor availability 对地理尾部风险影响很大。

**尚不能说：**S1+S2 普遍降低 GeoFM 公平差距。需要 TerraMind 或 THOR 的同因子复制和 paired CI。

### 2.4 AlphaEarth / GEE

**已观察：**

- Drive 正式 full-v2 包有 156,246 行、111 个国家，总体准确率约 0.7649；
- country Raw-BWER 约 0.1207，class 约 0.1652，country×class apparent BWER 约 0.3498；
- WorldCover 与 Dynamic World 一致率约 0.503；一致区准确率约 0.873，分歧区约 0.655；
- 90% conformal 目标的边际 coverage 约 88.99%，平均 set size 约 1.449；
- 70% 目标时平均 set size 小于 1，说明空集合诊断不可省略；
- 本地 unified package 仍有 placeholder lineage，Drive full-v2 才是正式证据源。

**正式能说：**全球平均覆盖/准确率掩盖国家、类别和交叉切片差异；地图产品分歧与高风险区域高度相关。

**尚不能说：**country×class 的 0.3498 全部是真实模型不公平。它同时受低支持、尾部选择、参考产品歧义和空间相关影响。

## 3. 代码级问题

### 3.1 旧尾部算法

当前 `src/rsfm_fairness_audit/bwer.py` 的 `compute_tail_risk` 使用：

```python
tail_n = ceil(len(valid_slices) * tail_fraction)
```

这不是离散部署测度的精确 AVaR。修复是 fractional boundary mass，而不是简单把 `ceil` 改成 `floor`。

### 3.2 默认 standardisation 错位

`BWERConfig.missing_balance_policy`、CLI 和多个任务适配器默认 `renormalize`。当某切片缺少目标层时，它把剩余 $q$ 重新归一化，导致每个切片使用不同标准人口。

本轮反例：A 的两类风险为 0.1/0.9，B 只观察第一类且风险 0.1，目标组成各 50%。逐组 renormalize 得到 A=0.5、B=0.1 的伪差距 0.4；共同可识别层上真实差距为 0。

### 3.3 cluster bootstrap 的 ID 合并

当前 bootstrap 抽中同一 cluster 多次时复制原行但保留原 ID。若 `cluster_key == slice_variable`，后续 group-by 会把重复克隆重新合并。

反例 `[1,1,0]`：正确的三次事件抽样在 (\beta=.5) 下 BWER 为 0.3333；合并原 ID 后变为 `[1,0]`，BWER 为 0.5。该 bug 改变推断总体，而非数值精度。

### 3.4 `bwer_v2.py` 名称冲突

该文件是 Sen1 post-hoc 流水线版本，内部仍调用旧 core，并默认 `renormalize`。若论文继续同时使用“BWER2”表示新指标，会造成代码版本与数学版本混淆。最终只公开 `BWER` / `GeoBWER`，旧文件保留兼容层。

### 3.5 现有测试保护了旧行为

当前测试覆盖支持阈值、missing policy、bootstrap 稳定性和 v2 输出，但部分测试把 `ceil` 与 `renormalize` 当作预期行为。升级时不能直接删除这些测试；应：

1. 把旧行为移到显式 `legacy_*` 测试；
2. 为新 core 新增性质测试；
3. 对旧 CLI 进行兼容测试；
4. 用 golden tables 验证只有预期字段和数值发生变化。

### 3.6 正式推断会静默退化

`audit_pipeline.py` 在配置的 cluster 字段不存在时只发 warning，随后把 cluster 设为 `None`。这会让本应按事件、location 或空间块推断的正式任务静默退化为普通样本 bootstrap。修复不是增加一条提示，而是：formal 模式缺 `independent_unit_id`/`cluster_id` 必须 hard fail；只有显式标记的 `diagnostic_iid` 才允许无 cluster 运行。

### 3.7 AlphaEarth 的 0.5°块不是统一空间尺度

当前 AlphaEarth 导出脚本用 `floor(lon*2)/2` 与 `floor(lat*2)/2` 生成 0.5°块。经度一度的地面距离随纬度缩小，且日期变更线与极区行为不等价，因此它可作为历史 split 标识，却不应作为最终空间推断的唯一 block。新协议保留原始坐标，并从 H3/S2 等地表索引或局部等面积块的候选尺度中，按非测试数据的相关范围和 coverage-power 门选择主尺度；0.5°结果降为敏感性比较。

## 4. 有限样本验证结果

可复算脚本：`finite_sample_estimator_validation.py`。

### 4.1 fMoW 式支持

| 场景 | 真 BWER | apparent plug-in 均值 | cross-fit confirmed 均值 | bootstrap 修正均值 |
|---|---:|---:|---:|---:|
| 同质零差异 | 0.0000 | 0.1088 | 0.0008 | 0.0733 |
| 中等尾部 | 0.0538 | 0.1121 | 0.0107 | 0.0792 |
| 强尾部 | 0.1076 | 0.1299 | 0.0444 | 0.1060 |

**推论：**没有单一有限样本点估计器在零差异、弱尾和强尾上都占优。plug-in 偏高；cross-fit 对弱尾偏低；简单 bootstrap bias correction 在零假设仍偏高；经验贝叶斯可能压缩真实尾部。因此最终产品应保留 apparent point，并把“至少能确认多少”作为独立证书，而不是宣称找到万能无偏估计器。

### 4.2 区间

普通一侧 Wald LCB 在 fMoW 零假设下覆盖率约 92.8%，假阳性约 7.2%；严格 Hoeffding/Bernstein 边界覆盖充分，但中等信号下过保守。主区间必须以覆盖率与 power 双门选择。

## 5. 新增空间相关模拟

可复算脚本：`design_validation.py`；结果：`diagnostics/spatial_band_simulation.csv`。

模拟包含 30 个组、48 个相邻空间位置、位置内重复和 AR(1) 空间相关。用 simultaneous group-risk band 传播到 BWER：

| 零差异方法 | 95% 覆盖率 | 假阳性证书率 | 平均区间宽度 |
|---|---:|---:|---:|
| 把所有观测当 i.i.d. | 76.7% | 23.3% | 0.037 |
| 以空间位置为 cluster | 96.1% | 3.9% | 0.064 |
| 六位置 spatial superblock | 97.2% | 2.8% | 0.088 |

中等尾部真值约 0.036 时，三者的正证书率约为 100%、82.8% 和 21.1%。

**推论：**空间聚类能修复欠覆盖，但超块过大可显著损失功效。当前最合理的冻结是“默认使用与独立部署单元匹配的 cluster/spatial multiplier simultaneous band，并做 block-size coverage/power 校准”，不是把固定六块写成万能默认值。

## 6. 指标构念风险

### 6.1 fairness 不是因果歧视的同义词

事件、国家、类别、sensor condition 都可以是部署切片，但伦理含义不同。GeoBWER 测量 **deployment-slice risk parity / reliability disparity**。只有在切片具有权益或资源分配含义时，才能进一步讨论社会公平；不能由一个高 country BWER 推断因果歧视。

### 6.2 分区本身是规范选择

国家、事件、网格和国家×类别回答不同问题。任何 BWER 数字都必须绑定：

```text
task / loss / prediction unit / slice definition /
deployment weights / beta / support / missingness /
split / inference unit / reference product / metric version
```

没有协议签名的两个 BWER 数字不应直接排名。

### 6.3 小样本不只在洪水

Sen1 的 (G=11) 很显眼，但 fMoW 国家支持长尾、AlphaEarth 国家×类别交叉稀疏同样严重。样本总量大不能保证每个尾部候选稳定。

### 6.4 分割风险必须固定聚合顺序

“先逐图算 IoU 再平均”与“先汇总 TP/FP/FN 再算事件 IoU”不是同一参数。主任务应使用事件级聚合混淆计数得到 (1-IoU)，并把图块级损失用于推断；不得在看到结果后选择更大的差距。

### 6.5 多标签 AP 不是简单样本期望

macro-AP 适合总体能力表，但不天然满足样本级可加风险接口。reBEN 主 BWER 应采用样本级 Hamming loss 或预注册 false-negative loss；`1-macro AP` 只作 cross-run modality 诊断。

## 7. 现有基础能复用多少

可直接复用：

- 数据下载、缓存、manifest 和准备 zip；
- 模型适配器与绝大多数已有 checkpoint；
- 规范化 audit table 思路、支持预检和任务 taxonomy；
- 现有 Raw/Selective 结果的多数后处理字段；
- AlphaEarth full-v2 数据和空间块 split；
- 报告、打包、sanity checks 与踩坑文档。

需要重写或扩展：

- BWER core、standardisation 和 bootstrap/inference；
- protocol signature、invalid states 和 comparison contract；
- fMoW 完整概率输出；
- Sen1 概率图和明确 independent unit；
- conformal/CRC 三类任务适配器；
- 新模型适配与同协议运行。

现有管线的正确评价是：**缓存、数据准备、绝大多数模型流程、预检和打包骨架可靠且高度可复用；核心指标、standardisation、正式推断、输出 schema 与 fail-fast 语义需要实质重构。**因此 BWER1 显著降低工程风险，但不能把升级理解成只替换一条公式。

结论：不是推倒重来。约 70%–80% 的数据、模型、预检和打包基础可保留；需要较大改造的是论文价值最高的审计核心与推断层。
